# データベースのこと

Supabase を使っています。このフォルダには、DBを作り直すためのSQLが入っています。

## ファイル

| ファイル | 何をするもの | いつ流すか |
|---|---|---|
| `01_schema.sql` | 土台。テーブル・型・RLS・関数・トリガー | 作り直すとき、最初に1回 |
| `02_community_icon.sql` | グループアイコンの列と、アイコンだけを変える関数 | 動いているDBに足すとき（01 にも入っています） |
| `03_community_icon_storage.sql` | グループアイコンの画像を avatars に上げる許可 | 保管庫を作ったあと |
| `91_clear_demo_users.sql` | 「デモで入る」で作られたゲストのアカウントだけを消す | 発表が終わったあと |
| `92_demo_community.sql` | 発表用のデモ用コミュニティ（空っぽ。ゲストだけが入る） | 発表の前。流すたびに空っぽに作り直します |
| `04_security.sql` | 許可（RLS）の見直し。01 より新しい、今の正しい形です | 03 のあと。**01 の許可を上書きします** |
| `seed.sql` | 確認用のダミーデータ | 何度でも。中で全部消してから入れ直します |
| `99_reset.sql` | まっさらにする | **危険。作り直すときだけ** |
| `history/` | 過去に流した差分。中身は `01_schema.sql` に入っています | もう流しません |

## 新しく作り直す手順

```
① 99_reset.sql     まっさらにする
② 01_schema.sql    土台を作る
③ seed.sql         ダミーデータを入れる
④ 保管庫を作る      ← SQLではできません。下を見てください
⑤ 03_community_icon_storage.sql   グループアイコンの画像の許可
⑥ 04_security.sql                 許可の見直し（01 の許可を正しい形に作り直します）
```

> **許可を足したいときは、ダッシュボードの画面から足さずに、SQL ファイルに書いてください。**
> 画面から足すと、ファイルと本番がずれて、どこに穴があるか分からなくなります
> （04_security.sql は、実際にそうなっていたのを直したものです）。

## 保管庫（Storage）

画像の置き場所です。**SQLでは作れない**ので、ダッシュボードから手で作ります。

```
Supabase → Storage → New bucket
```

| 名前 | 公開 | 何を入れるか |
|---|---|---|
| `avatars` | **公開** | プロフィールのアイコン |
| `posts` | 非公開 | ご報告の写真 |
| `drawings` | 非公開 | 手書きのお祝い |
| `cards` | 非公開 | メッセージカード |

`avatars` だけ公開なのは、相関図で全員のアイコンを出すためです。非公開だと、
人数ぶん期限付きURLを発行することになり、そのぶん表示が遅くなります。

ほかの3つは非公開です。**コミュニティの中の人にしか見せないもの**なので、
見るたびに期限付きURL（1時間）を発行しています。

## 設定（ダッシュボード側）

SQLに含められない設定です。作り直したときは、ここも確認してください。

```
Authentication → Providers → Email
  Confirm email … OFF（ハッカソン中。本番ならONに戻す）

Authentication → Providers → Google
  有効にしておく
```

## 鍵について

`.env.local` と Vercel の環境変数に入れます。

| 名前 | 置く場所 | 性質 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 両方 | 公開してよい |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 両方 | 公開してよい（RLSが守る） |
| `SUPABASE_SERVICE_ROLE_KEY` | 両方 | **絶対に出さない**。RLSを無視できる |

`NEXT_PUBLIC_` が付いているものはブラウザに配られます。
3つめに付けてはいけません。付けると、誰でもDBを全部読み書きできます。

## 覚えておくとよいこと

**RLS（行レベルセキュリティ）がこのアプリの本体です。**
画面側の `if` ではなく、DB側が「誰に何を見せるか」を決めています。

- `posts` / `communities` … そのコミュニティのメンバーしか読めません
- `profiles` … 誰でも全員分読めます（相関図に名前を出すため）
- `recovery_codes` … 発行した本人しか読めません
- `time_capsules` … 開封日を過ぎた行しか返ってきません

**テーブルを増やしたら、RLSの設定も必ず書いてください。**
書き忘れると、鍵を持っている人（＝アプリを開いた人全員）が
中身を全部読み書きできる状態になります。
